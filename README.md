# Unkn0WnTorrent

Быстрый торрент-клиент для Windows на Rust с нативным интерфейсом и одним `.exe` на выходе.

Движок — [librqbit](https://github.com/ikatson/rqbit): полноценный BitTorrent-клиент с DHT, uTP,
UPnP, PEX, магнитами и быстрым возобновлением. Интерфейс — egui/eframe.

## Скачать

Готовый `Unkn0WnTorrent.exe` — в разделе [Releases](https://github.com/Unkn0Wms1337/Unkn0WnTorrent/releases).
Один файл, без установки и без DLL: распакуйте и запустите.

## Возможности

- **Только максимальная скорость загрузки**: лимита на скачивание нет — 2000 пиров на торрент,
  TCP + uTP, UPnP, DHT, LSD, PEX и увеличенное окно запросов (до 1024 блоков на пира).
  Отдача при загрузке по умолчанию ограничена 1 МБ/с, чтобы раздача не душила скачивание
  (см. [«Отдача при загрузке»](#отдача-при-загрузке)); после завершения лимит снимается.
- **Щадящий режим**: процесс работает с приоритетом ниже обычного (в свёрнутом окне — самый
  низкий), интерфейс перерисовывается 2 раза в секунду, потоки диска ограничены. Клиент не
  мешает играм, Discord и микрофону — проверено: ~0,2 с CPU за 10 с при активной загрузке.
- **Публичные трекеры**: 14 трекеров автоматически добавляются к каждому торренту, опрос раз
  в минуту — больше сидов и стабильнее скорость. Сглаженный индикатор не «прыгает» каждую секунду.
- **Очередь и приоритеты**: у каждого торрента приоритет (высокий / обычный / низкий).
  Можно ограничить число одновременных загрузок — тогда качаются самые приоритетные,
  а остальные ждут. `0` (по умолчанию) — качать всё сразу на максимальной скорости.
- **Выбор файлов**: внутри торрента можно снять галочки с ненужных файлов и качать только нужное.
- **Тёмный интерфейс без рекламы**: список торрентов, фильтры, поиск и панель деталей
  в стиле классических клиентов — только чёрный фон и нужная информация.
- **Своя папка для каждой игры**: по умолчанию всё скачивается в
  `%USERPROFILE%\Downloads\Unkn0WnTorrent\<Название игры>`. Базовую папку можно изменить
  в настройках (плюс кнопка «Открыть папку загрузок»).
- **Уведомление Windows** о завершении загрузки: название торрента, папка, звук.
- **Магниты, .torrent-файлы, drag & drop** в окно программы.
- Пауза/продолжение, удаление записи или торрента вместе с файлами, открытие папки.
- Сохранение списка торрентов и быстрый докач после перезапуска (fastresume).
- Порт, UPnP и uTP настраиваются; один экземпляр приложения (защита от конфликтов порта).
- Сборка в **один exe** со статическим MSVC runtime — Visual C++ Redistributable не нужен.

## Сборка

Нужен только Rust (stable, MSVC toolchain):

```powershell
cargo build --release
```

Готовый файл: `target\release\Unkn0WnTorrent.exe`.

Или:

```powershell
.\build.ps1
```

Скрипт соберёт релиз и положит копию в `dist\Unkn0WnTorrent.exe`.

Статическая линковка CRT включена в `.cargo/config.toml` (`+crt-static`), поэтому рядом
с exe не нужны никакие DLL.

## Где хранятся настройки

`%APPDATA%\Unkn0WnTorrent\`

- `settings.json` — настройки;
- `session\` — состояние торрентов (докачка после перезапуска);
- `priorities.json` — приоритеты;
- `logs\` — логи и `panic.log` (полезно, если что-то пошло не так).

Настройки порта, UPnP и uTP применяются после перезапуска приложения. Приоритеты,
папка и уведомления применяются сразу (папка — к новым торрентам).

## Отдача при загрузке

### Главное, что нужно понять

Лимит отдачи **не задаёт скорость скачивания**. «Вниз» и «вверх» — независимые направления,
и загрузка упирается в сидов, их каналы и вашего провайдера, а не в этот ползунок.
Лимит нужен для другого: если раздача занимает аплинк на 100 %, подтверждения (ACK)
и запросы кусков встают в очередь, и скачивание проседает. Классическая картина —
«в диспетчере задач 900 Мбит/с, а в клиенте 6 МБ/с», или «микрофон в Discord захлёбывается».

Правило: **оставляйте ~30 % аплинка свободными**, то есть ставьте около 70 % от скорости
отдачи по тарифу. Поле «Отдача при загрузке» — в **КБ/с** (1 МБ/с = 1024 КБ/с).
Лимит действует только пока что-то качается; после завершения отдача идёт без ограничений.

### Таблица лимита отдачи

Смотрите на **скорость отдачи (upload) из своего тарифа**, а не на скорость скачивания.
Биты и байты не путайте: 1 МБ/с = 8 Мбит/с. Это самая частая ошибка.

| Аплинк по тарифу | Лимит 70 % | Поле «Отдача при загрузке», КБ/с |
|---:|---:|---:|
| 10 Мбит/с | 0,9 МБ/с | 896 |
| 20 Мбит/с | 1,75 МБ/с | 1792 |
| 30 Мбит/с | 2,6 МБ/с | 2688 |
| 50 Мбит/с | 4,4 МБ/с | 4480 |
| 100 Мбит/с | 8,75 МБ/с | 8960 |
| 200 Мбит/с | 17,5 МБ/с | 17920 |
| 300 Мбит/с | 26,25 МБ/с | 26880 |
| 500 Мбит/с | 43,75 МБ/с | 44800 |
| 1000 Мбит/с | 87,5 МБ/с | 89600 |

Как выбрать своё значение:

- **Асимметричный тариф** (типичный домашний): смотрите только на upload. Например,
  1000/100 Мбит — аплинк 100 Мбит/с = 12,5 МБ/с, значит лимит ≈ 8960 КБ/с (70 %).
- **Тариф неизвестен**: запустите Speedtest и возьмите измеренный upload в Мбит/с.
  Не ориентируйтесь на скорость загрузки — она ничего не говорит об отдаче.
- **Несколько устройств в сети** (телевизор, телефон, консоль) — оставьте не 30 %, а 40 %
  запаса, то есть 60 % от аплинка.
- **Минимум — 1 МБ/с (1024 КБ/с)**: при слишком низкой отдаче пиры хуже отдают данные вам.
- Для обычной домашней загрузки редко нужно больше 4–8 МБ/с отдачи: этого хватает
  для взаимности с пирами и нормального рейтинга. Большие значения — только для сидинга.
- `0` — без лимита. Нормально для симметричного канала, если вы не замечаете просадок
  в скачивании и голосовом чате.
- Если ставите значение «на глазок» и микрофон в Discord начинает лагать — уменьшите лимит
  на 20–30 %, а не скорость скачивания: душит канал именно отдача.

## Почему это быстрее «обычных торрентов»

Скорость торрента зависит не только от клиента, но и от раздачи: количества сидов, их каналов,
вашего провайдера, NAT и диска. Что делает этот клиент:

- открывает входящий порт через UPnP и слушает TCP и uTP одновременно;
- использует DHT, PEX и LSD, а не только трекеры;
- не ограничивает скачивание и аккуратно придерживает отдачу, чтобы она не забивала канал;
- держит увеличенное окно запросов (до 1024 блоков на пира);
- чаще опрашивает трекеры и держит много пиров;
- пишет на диск потоково, без лишних копий.

Если провайдер режет BitTorrent-трафик или вы за NAT без UPnP — скорость будет ограничена
сетью, а не программой. В таком случае поможет проброс порта вручную или VPN.
